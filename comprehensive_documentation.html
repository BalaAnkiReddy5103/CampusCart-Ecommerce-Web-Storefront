1. Executive Summary

CampusCart – Indian Campus Edition is a production-grade, single-page web storefront created to resolve the recurring procurement challenges experienced by college students across Indian universities and technical institutes. Commercial platforms (e.g., Amazon, Flipkart) are ill-suited for immediate student needs: they suffer from delivery lead times of 2 to 4 days, require minimum spend quotas to qualify for free shipping, and carry generic consumer catalogs rather than specialized curriculum requirements.

CampusCart delivers an instantaneous, localized academic storefront allowing students to procure engineering textbooks (GATE, CSE, ECE, Mechanical), drafting tools, laboratory coats, scientific calculators, and computer accessories with sub-second response times. Constructed strictly using native web standards—HTML5, CSS3, and ES6+ JavaScript—with zero framework dependencies, CampusCart guarantees frictionless execution across desktop and mobile browsers alike.

2. Problem Statement & Market Context

Higher education institutions in India represent intense micro-marketplaces with sharp seasonal demands. At the beginning of semesters and during examination periods, thousands of students require exact textbooks, lab instruments, and technical supplies simultaneously. The prevailing ecosystem suffers from three major structural frictions:

  • Academic Urgency & Exam Pressure: Laboratory submissions and semester exams cannot wait 72 hours for parcel couriers. Immediate access to standard authors (e.g., B.S. Grewal, Horowitz, Morris Mano) is critical.
  • Economic Inefficiency: Imposing a ₹40–₹60 delivery fee on a ₹150 exam notebook pack or a ₹45 drawing template creates disproportionate friction for cost-conscious students.
  • Information Asymmetry: Students often waste valuable study hours visiting physical cooperative stores only to find required calculators or drafters sold out.

CampusCart resolves these challenges by consolidating real-time inventory tracking, local hostel delivery simulation, and multi-parameter filtering into a zero-latency client application.

5. Component-by-Component Frontend Architecture

5.1 Responsive Navigation Bar & Live Badge Counter

The navigation header is fixed to the viewport top with a subtle backdrop blur effect (backdrop-filter: blur(8px)). It contains:

  • Brand Logo: CampusCart logo featuring an Indian saffron graduation mortarboard icon and bold deep navy typography.
  • Smooth-Scroll Navigation Links: Quick jumps to #home, #products, #categories, #about, and #contact.
  • Live Cart Counter: A high-visibility badge displaying real-time quantity $N = \sum q_i$. It animates with a pulse effect whenever items are added or removed.
  • Mobile Drawer Trigger: An animated hamburger button transitioning into a slide-out drawer on screens below $768\text{px}$.

5.2 Hero Section & Promotional Call-to-Action (CTA)

The storefront entrance features a high-impact hero banner designed to connect with Indian engineering and university students:

  • Headline: "Apna Campus, Apni Dukaan – Everything You Need for Campus Life."
  • Core Value Propositions: Student discounts up to 35%, verified genuine academic gear, zero minimum order requirement, and instant hostel delivery within 2 hours.
  • Primary Action: "Shop Now" button with smooth scroll targeting the product grid.

5.4 Product Listing & Dynamic Card Architecture

Product cards are dynamically instantiated via JavaScript template literals. Every card incorporates:

  • Discount & Stock Badges: Visual pills indicating savings percentage (e.g., 28% OFF) and urgent stock alerts (e.g., Only 2 left!).
  • Smart Image Box: Fluid image container with pre-allocated aspect-ratio: 4/3 to guarantee Cumulative Layout Shift (CLS) is zero.
  • Dual Pricing: Discounted current price in bold Indian Rupees (₹) alongside struck-through Original MRP.
  • Reactive Action Button: "Add to Cart" button that automatically shifts to a disabled, grayed-out state if $\text{stock} = 0$.

5.5 Composite Search, Filter & Multi-Sort Toolbar

A persistent, multi-faceted filtering strip that operates without inter-filter conflict:

  • Live Keyword Search: Debounced query input matching product titles, descriptions, and category tags.
  • Category Select: Dropdown synchronizing with the top visual category cards.
  • Sorting Controller: Re-orders results by Featured, Price (Low to High), Price (High to Low), or Top Rated.
  • In-Stock Only Filter: Checkbox instantly eliminating depleted inventory from view.
  • Clear All Filters: Instant one-click reset restoring the complete catalog.

5.6 Shopping Cart Drawer & State Controller

The shopping cart resides in a modern, fixed right-hand slide-out drawer with a darkened backdrop overlay. Features include:

  • Itemized Rows: Displays thumbnail, name, unit price, quantity increment/decrement controls, and a delete button.
  • Physical Stock Guard: The increment button (+) disables automatically when quantity matches available warehouse stock.
  • Financial Summary: Tally of Subtotal, Total Savings, Delivery Fee (₹0 for orders ≥ ₹299), and Final Payable Amount.
  • Empty State Screen: Engaging graphic and "Start Shopping" button when cart quantity is 0.
⚠ State Persistence Guarantee
Every cart mutation immediately serializes the cart array to localStorage. Even if a student abruptly closes their browser or refreshes the page, their selected items, quantities, and prices are fully restored.

5.7 Indian Checkout Modal & Form Validation

Clicking "Proceed to Checkout" opens an accessible modal dialog containing:

  • Student Details: Full Name, College Email, and Indian 10-Digit Mobile Number.
  • Hostel & Campus Delivery Address: Room/Hostel block, Campus area, City, Indian State dropdown, and 6-Digit PIN Code.
  • Dynamic Order Summary: Recapitulates the itemized tally, delivery fee, and total amount in ₹ INR.
  • Real-Time Input Validation: Evaluates fields against Indian regulatory standards with instantaneous visual error labels.

5.8 Order Confirmation Modal & Unique Token Generator

Upon successful checkout validation, the system triggers the Order Confirmation view:

  • Unique Order ID: Generates an official tracking token formatted as CC-YYYYMMDD-XXXX (e.g., CC-20261123-8E2B).
  • Hostel Delivery ETA: Displays an estimated delivery window of 2 hours directly to the student's room.
  • Automatic State Flush: Purges the cart from memory and localStorage, resetting the badge counter to 0.

5.9 Dynamic Toast Notification System

Provides immediate, non-blocking user feedback for every critical action:

  • SUCCESS "Higher Engineering Mathematics added to cart!"
  • WARNING "Maximum stock reached for this product."
  • ERROR "Please correct the errors in the checkout form."

6. Source Code Deep-Dive & Function Reference

6.1 `products.js` – Inventory Catalog & REST API Integration

Houses the primary data registry, external REST API communications, and image fallback management:

  • FALLBACK_PRODUCTS: Immutable array containing 24+ curated Indian campus products spanning all 5 categories with prices, MRP, stock counts, ratings, and image links.
  • fetchProducts(): Asynchronously queries https://dummyjson.com/products?limit=30 using Promise.race() with a 4-second timeout. If the request fails, times out, or runs offline, it returns FALLBACK_PRODUCTS without crashing.
  • mapApiProduct(item): Normalizes third-party API objects to the internal CampusCart schema, converting USD to INR ($1 = ₹83) and mapping categories.
  • handleImageError(img): Handles broken or unreachable remote image links by inserting an inline SVG placeholder with the product name.

6.2 `cart.js` – State Management & Financial Math

Encapsulates cart manipulation and persistence logic:

  • getCart(): Reads from localStorage.getItem('campuscart_cart_items'), securely parses JSON via try...catch, and returns the array.
  • saveCart(cart): Writes updated cart back to localStorage and triggers the live counter badge update.
  • addToCart(productId): Verifies product existence and stock availability. Increments existing item quantity or pushes a new item.
  • updateCartQuantity(productId, delta): Adjusts quantity by $\pm 1$. Enforces the invariant $1 \le q_i \le \text{stock}$. Disables increment button when stock ceiling is reached.
  • removeFromCart(productId): Filters out specified product and refreshes cart UI.
  • clearCart(): Purges all items from memory and storage.
  • calculateCartTotals(): Computes Subtotal, Delivery Fee (₹0 if $\ge ₹299$, else ₹30), and Grand Total.

6.3 `filters.js` – Multi-Predicate Filtering & Sorting Engine

Ensures seamless interaction between search queries, categories, stock status, and sorting criteria:

  • filterState: Global state holding searchQuery, category, inStockOnly, and sortBy.
  • applyFilters(products): Applies consecutive predicate filtering (Search $\land$ Category $\land$ Stock) followed by array sorting.
  • debounce(func, delayMs): Delays live search execution by 250ms to prevent CPU saturation during fast keyboard entry.

6.4 `checkout.js` – Validation Logic & Order Simulation

Handles the simulated procurement finalization and strict regulatory compliance:

  • validateIndianMobile(val): Tests against DoT regex /^[6-9]\d{9}$/.
  • validateIndianPin(val): Tests against postal regex /^[1-9][0-9]{5}$/.
  • validateEmail(val): Enforces standard RFC 5322 email patterns.
  • validateCheckoutForm(): Validates all inputs and displays inline error styling.
  • generateOrderId(): Generates tokens formatted as CC-YYYYMMDD-XXXX.
  • handleCheckoutSubmit(e): Orchestrates order placement, displays loader, opens confirmation modal, and clears the cart.

6.5 `main.js` – App Orchestrator & Event Delegation

The core controller that boots the application on DOMContentLoaded:

  • initApp(): Orchestrates product fetching, cart badge initialization, event listener registration, and initial grid rendering.
  • renderProductGrid(items): Renders product cards into the DOM using optimized DocumentFragment nodes to minimize browser reflows.
  • showToast(msg, type): Spawns self-dismissing toast notifications.
  • setupModalHandlers(): Binds keyboard (Escape key) and overlay click events for closing modals and drawers.

6.6 `style.css` – Design Tokens & Layout Architecture

A comprehensive stylesheet establishing the design language:

  • CSS Variables: Standardizes brand colors (Navy #0f172a, Saffron #f97316), surface backgrounds, typography scales, and shadows.
  • Balanced Spacing: Uses an adaptive container with max-width: 1280px and fluid padding clamp(1rem, 3vw, 2.5rem) eliminating left/right whitespace gaps.
  • Responsive Breakpoints: Clean transitions across desktop, tablet, and mobile displays without horizontal scrollbars.

8. Core Algorithms & Mathematical Logic

8.1 Multi-Predicate Filtering Pipeline

Products are evaluated through a strict conjunction of three predicate functions:

const filtered = allProducts.filter(p => {
  const matchesSearch = !query || 
    p.name.toLowerCase().includes(query) || 
    p.description.toLowerCase().includes(query);
  const matchesCategory = category === 'all' || p.category === category;
  const matchesStock = !inStockOnly || p.stock > 0;

  return matchesSearch && matchesCategory && matchesStock;
});

8.2 Cart Inventory Invariant Protection

The cart prevents adding more items than available in warehouse stock:

function addToCart(productId) {
  const product = catalog.find(p => p.id === productId);
  const existing = cart.find(item => item.id === productId);

  if (existing) {
    if (existing.quantity >= product.stock) {
      showToast("Maximum stock limit reached!", "warning");
      return;
    }
    existing.quantity += 1;
  } else {
    cart.push({ ...product, quantity: 1 });
  }
  saveCart(cart);
}

8.3 Financial Calculations & Rupee Formatting

  • Subtotal: $\sum (p_i \times q_i)$
  • Delivery Fee: ₹0 if Subtotal $\ge$ ₹299, else ₹30.
  • Grand Total: $\text{Subtotal} + \text{Delivery Fee}$.
  • INR Number Formatting: '₹' + Number(amt).toLocaleString('en-IN').

10. Security, Performance & Error Resilience

10.1 XSS Prevention Strategy

All user inputs and dynamic strings are rendered through textContent rather than unescaped innerHTML. Where template literals are required, strings are sanitized through an HTML entity encoder to prevent script injection.

10.2 LocalStorage Quota & Corrupt Data Guard

Direct JSON.parse() on browser storage can trigger unhandled exceptions if the user tampers with the data. CampusCart protects every storage access: 

function getCart() {
  try {
    const raw = localStorage.getItem('campuscart_cart_items');
    return raw ? JSON.parse(raw) : [];
  } catch (err) {
    console.error("Corrupted cart detected. Resetting.", err);
    localStorage.removeItem('campuscart_cart_items');
    return [];
  }
}

10.3 Network Resilience & Offline Fallback

The application executes perfectly in offline or restricted classroom networks. If fetch() fails, the system automatically falls back to FALLBACK_PRODUCTS without UI disruption.

10.4 Image Asset Resilience

All image tags feature inline onerror event handlers that seamlessly replace broken image URLs with a clean, lightweight SVG vector placeholder.

To publish the project to GitHub and deploy it live via GitHub Pages:

cd "E:\10K CODERS\Projects\CampusCart"

# 2. Link your local repository to your remote GitHub repo

# 4. Push all commits to GitHub
